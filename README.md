# DocChat — Chat with a Document using Groq

A Retrieval-Augmented Generation (RAG) app built with **Streamlit**, featuring a chat-style interface. Upload a `.txt` file in the sidebar and have a conversation about its content — answers are generated by the **Groq API**, grounded only in the text you provide.

This is a UI variant of the original single-page RAG app — same retrieval pipeline, presented as a chat experience with a sidebar for document management and settings.

## How It Works

1. **Upload** — you upload a `.txt` file from the sidebar.
2. **Chunk** — the text is split into overlapping chunks (~800 characters each).
3. **Embed** — each chunk is converted into a vector embedding locally using `sentence-transformers` (`all-MiniLM-L6-v2`). No API call or cost for this step.
4. **Retrieve** — each question you type is embedded the same way, and the most similar chunks are found via cosine similarity.
5. **Generate** — the retrieved chunks + your question are sent to the **Groq API** (`llama-3.3-70b-versatile`), which generates an answer grounded in that context, shown in a chat bubble.

```
.txt file → chunk → embed (local) → store in memory
                                        ↓
question (chat input) → embed (local) → similarity search → top chunks
                                        ↓
                          Groq LLM → grounded answer (chat bubble)
```

## Prerequisites

- Python 3.9+
- A free Groq API key from [console.groq.com](https://console.groq.com)

## Setup

**1. Move into the project folder:**
```bash
cd rag-streamlit-app
```

**2. Create and activate a virtual environment (recommended):**
```bash
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
```

**3. Install dependencies:**
```bash
pip install -r requirements.txt
```

**4. Add your Groq API key**

Open `.env` and replace the placeholder:
```
GROQ_API_KEY=your_groq_api_key_here
```

## Running the App

```bash
streamlit run app.py
```

The app opens automatically at `http://localhost:8501`.

## Usage

1. In the **sidebar**, upload a `.txt` file — it's automatically chunked and indexed.
2. Once indexed, the sidebar shows the active document name and chunk count.
3. Type a question in the **chat box** at the bottom of the main panel.
4. The assistant replies as a chat message; expand **"📚 Sources used"** under any reply to see exactly which chunks were retrieved and their similarity scores.
5. Keep chatting — the full conversation stays visible. Use **🗑️ Clear chat** in the sidebar to start over without re-uploading.
6. Uploading a new file resets the chat and re-indexes automatically.

## Configuration

Tweakable directly in `app.py`:

| Setting | Location | Default | Notes |
|---|---|---|---|
| Groq model | `GROQ_MODEL` | `llama-3.3-70b-versatile` | Any model available in your Groq account |
| Chunk size | `chunk_text()` | 800 characters | Larger = more context per chunk, fewer chunks |
| Chunk overlap | `chunk_text()` | 150 characters | Prevents losing context at chunk boundaries |
| Chunks retrieved (top-k) | Sidebar slider | 4 | Adjustable live in the app, 1–8 |
| Embedding model | `load_embedder()` | `all-MiniLM-L6-v2` | Small and fast; swap for a larger model for better accuracy |

## Notes & Limitations

- **Single file only** — one `.txt` file at a time; uploading a new file replaces the previous session and clears the chat.
- **In-memory storage** — embeddings and chat history live in `st.session_state`, not persisted to disk. Restarting the app clears everything.
- **First run downloads the embedding model** (~80MB) — needs internet once, then cached locally.
- **Scaling up** — for large documents, multiple files, or persistence across sessions, swap the in-memory numpy search for a vector database like FAISS or Chroma.
- **Cost** — embeddings run locally at no cost. Only the final answer generation calls the Groq API (Groq's free tier is generally sufficient for testing).

## Troubleshooting

- **`GROQ_API_KEY not found`** — make sure `.env` is in the same folder as `app.py` and contains a valid key with no quotes.
- **Slow first request** — the embedding model downloads on first use; subsequent runs are fast.
- **Answers say "I don't know"** — the retrieved chunks may not contain relevant content; try increasing the top-k slider or rephrasing the question.
- **Chat not clearing** — use the "🗑️ Clear chat" button in the sidebar rather than refreshing the browser, so the indexed document stays loaded.
